# OpenCLI：首次接入与按需取证

**BOSS 直聘例外：** 先按 [BOSS 通道路由](boss-routing.md) 使用 Agent Reach 的专用 `boss` 客户端，只有允许的普通不可用情形才用 `opencli boss` 备用。遇到安全验证、账号/环境风险或限流时，不通过主备切换继续访问。

## 默认使用者尚未安装

首次使用时检查是否能运行 `opencli --version`；不要因为 skill 作者的机器有就假定其他人也有。检查失败时区分未找到命令、执行策略或运行错误，不能把所有情况都写成“未安装”。

尚未安装时，可自然提示：

> 我可以借助 OpenCLI 查询更多岗位、学习资源和实际案例。你这边还没有这个工具，需要我帮你安装吗？也可以先跳过，我们继续整理资料和聊方向。

只问一次，保留本次选择；拒绝或暂缓后不反复提醒。资料导入、核对和聊天均可继续。宿主另有适用搜索/网页读取工具时可以用，并说明实际来源；没有可用取证工具时保留候选和证据缺口，不能装作已经查证。

## 用户同意安装后

使用当时官方说明核对安装方式与运行环境：

- [官方仓库](https://github.com/jackwener/opencli)
- [官方安装说明](https://opencli.info/docs/guide/installation.html)

常见 CLI 安装入口为 `npm install -g @jackwener/opencli`，执行前核对 Node/npm 是否存在、当前官方版本的运行要求与安装权限。得到安装 CLI 的明确同意才安装；不能自行升级已有可用版本、安装其他工具、改代理或重启服务。环境缺前置条件时说明具体缺什么，征求相应安装同意，不把同意 OpenCLI 扩成任意环境修改。

安装后核对 `opencli --version` 与 `opencli --help`。CLI 可运行只证明安装完成，不证明浏览器、账号或某网站可用。需要浏览器能力时按当前版本说明引导连接 Browser Bridge；扩展安装、网站登录、验证码由用户完成，不读取或展示 cookies、令牌。连接不通就说明缺口，不自动重启浏览器或现有服务。

## 使用当前机器的命令

OpenCLI 版本之间可能有参数与输出差异。先读本机帮助，不从官网最新示例推断旧版本语法；缓存本次已读到的能力和参数，不每轮重查。

常用发现入口（仍以本机帮助为准）：

```text
opencli --help
opencli list -f json
opencli <site> --help -f json
opencli <site> <command> --help
opencli skills read opencli-usage
```

优先适用的站点只读适配命令。查看命令用途、参数和 access 标识，不能仅凭 `cookie`/`ui` 等连接策略认定只读。招聘搜索与详情、课程内容、项目资料、相关经验正文可以支撑研究；不调用发消息、打招呼、投递、发布、购买、关注、收藏等写操作，不读取与本轮无关的私信、浏览历史或私人账号资料。

发现能力时，已知站点先看该站帮助；需要全量目录时在本地解析完整输出，再只返回相关 `site/name` 与用途。不能用模型收到的截断列表或错误字段匹配，断言某类站点不存在。对本机 JSON 形状和参数先核对，帮助查询不算实际内容检索。

为行业研究分别寻找一手变化、实际需求和社区讨论的读取路径，不要发现招聘适配器后就只查招聘。知乎需要登录不等于所有社区都不可读；优先转用相关且可访问的其他公开讨论，或在确有必要时询问用户是否愿意登录该站。

搜索结果保留完整的标题、网址、日期与必要上下文，再挑相关原文/详情核对；不要只截取薪资、学历或开头若干行后归纳整个行业。关键词改变仍返回同批无关岗位时，先检查搜索是否生效、结果是否是推荐流、筛选是否过窄，不能据此宣布某类机会不存在。检索覆盖的范围只按实际读到的样本报告。

没有适配器时，若当前版本提供通用网页读取，可按实际帮助使用。例如仅在本机帮助确认支持后使用：

```text
opencli web read --url <工具实际返回的来源网址> --stdout true --download-images false
```

占位符是参数说明，不能原样执行。优先只返回正文，避免为一次核对默认创建网页导出目录或下载图片。还需更底层浏览器能力时，先读当前安装附带的 `opencli-browser` 指导；不为这个规划任务另写或修补站点适配器。

需浏览器连接的命令首次运行前，用本机支持的诊断方式检查；公共 HTTP 或本地命令不因为浏览器未连接而一律判不可用。若有多个浏览器配置且未明确当前所需配置，只询问使用哪个，单次命令显式指定，不擅自修改全局默认配置。

研究查询只传必要的通用条件，如岗位、技能、城市；不把姓名、联系方式或整份用户资料塞进搜索。保存返回来源的实际标题、网址、日期、范围及支持内容，按 [比较与证据](recommendation-and-evidence.md) 审查。

## 失败与停止

### 把渠道缺口变成用户能完成的一步

遇到缺少登录、授权、访问权限或配置时，先判断这个渠道能补哪项研究缺口，以及现有公开来源是否已经足够。渠道有独特或重要价值时，主动请用户协助，不要仅宣布失败，也不要只因一个平台失败就放弃社区或需求取证。已有等效来源时优先继续研究，不为接通工具而收集更多账号。

一次只引导当前最有用的一个渠道，用人话交代三件事：**哪个渠道缺什么、它会帮助判断什么、用户下一步怎样做**。例如：

> 知乎这边还没有登录，我想读几条从业者的实践和质疑，核对这个方向实际做起来有哪些难点。你可以在自己的浏览器登录后告诉我；也可以把相关讨论的链接或正文发来，暂时跳过也可以。

这只是示例，不代表每次都需要知乎，也不能未经实际检查就声称缺少登录。选项服务于当前缺口，不要一口气列出全部平台和安装步骤。

| 实际缺口 | 可以怎样引导 | 补充后怎样继续 |
|---|---|---|
| 网站未登录、登录已过期 | 请用户在本人浏览器中登录对应网站，告诉助手已完成；能打开准确登录页时可在用户需要后协助打开。 | 用本机支持的登录状态/只读命令检查一次；确认可读后，继续原研究问题，而不是重问个人情况。 |
| 多浏览器配置，当前连接的不是用户登录的那个 | 说明可能是浏览器配置不同，请用户指出所用配置；按当前帮助发现配置，单次命令显式选择。 | 核对实际连接及站点状态，不因用户说“我已登录”就假定当前 CLI 已连到该账号；不改全局默认。 |
| 需额外权限、会员或页面仅本人可见 | 说明实际访问限制，可请用户提供自己有权分享的相关正文、截图或导出材料；不默认要求购买或开通权限。 | 区分用户提供材料与助手直接读取；标明来源和可见范围，不声称读到了整站或完整讨论。 |
| 搜索服务缺少 API 配置 | 说明是哪项服务未配置，先看 OpenCLI 或其他已有渠道能否完成；用户愿意配置时，只指引其在工具自身的安全设置中填写。 | 检查服务是否可用；不用聊天收取密钥，不读取或打印凭证，也不为了一个搜索源强迫配置。 |
| 平台无可用适配命令、页面读不到、需要验证码 | 可请用户提供准确网址、相关文字、截图或可分享的导出文件；验证码与平台要求的人工操作由用户自己完成。 | 通过现有能力读取实际拿到的材料；不能读的部分继续标缺口，不绕过访问限制，也不自动开发适配器。 |

用户提供网址后再实际读取；拿不到正文时不能把“有链接”当证据已补齐。提供截图或文字时保留其材料性质、来源日期与范围，分清本人经历、转述和平台讨论，不把一张截图当总体舆论。

用户同意登录或配置，不代表同意发送消息、投递、发布等写操作。不要索取登录密码、短信/邮件验证码、Cookie、浏览器会话令牌或 API 密钥；用户主动贴出秘密时也不复述或写进规划记录，引导其只在原服务的安全入口处理。

用户选择跳过、拒绝登录或暂时不能提供材料后，记录本会话的渠道选择和研究缺口，继续可进行的研究，不每轮重问。同一个未变化的失败不重复检查；用户补充完成或连接状态确有变化后再验证一次。验证未通过则说清仍缺什么，不虚报接通，不把重新安装/重启服务作为默认下一步。

### 有限排查与继续研究

区分命令不存在、安装失败、桥接未连接、未登录、访问限制、空结果和内容不支持结论。失败后先看现有错误和帮助；有明确可纠正的参数问题可纠正一次，同一原因不反复重跑。不自动升级、修补适配器或绕过登录与访问限制。

一站失败不等于所有来源不可用。转用适用的其他来源或工具时，仍遵守研究范围与查询预算；到上限就说明证据缺口，继续不依赖它的对话。不能因为装了 CLI、命令被列出或搜索有结果，就报告该站内容已成功读取。安装、诊断、搜索失败都不能代替行业研究；“本轮没查成”也不能给未经核对的市场、技术或收入断言免责。

在 Windows 上将 JSON 输出交给其他程序时注意 UTF-8；旧 PowerShell 的文本管道可能改变字符。若 JSON 解析异常，先用工具自身 JSON 输出或直接以 UTF-8 捕获原进程输出定位，不篡改来源文本来强行解析。

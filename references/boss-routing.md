# BOSS 直聘：专用通道优先，OpenCLI 备用

本文件只规定研究所需的只读访问。首选是 **Agent Reach 接入的 BOSS 专用客户端 `boss`（boss-agent-cli）**；备用才是 `opencli boss`。Agent Reach 只是路由器，不能把“通过 Agent Reach 调用了 OpenCLI”说成已经使用不同的专用通道。

## 首次使用与就绪检查

1. 检查 Agent Reach 是否可用。已安装时按其当前 `SKILL.md` 和 `references/career.md` 的 BOSS 指导操作，并运行 `agent-reach doctor --json` 查看当前 BOSS 状态。
2. 核对 `boss --help` 及所需只读命令帮助。专用浏览器、登录态和连接是否就绪按当前指导验证；`active_backend: null` 单独不能证明不存在后端，`boss status` 单独也不能证明浏览器已经登录。
3. Agent Reach、专用客户端或连接尚未配置时，用一句话说明“这个专用通道还需配置/登录，是否希望我协助”，得到相应同意才安装或配置。也允许用户提供 JD 材料、暂时跳过，或在下方允许的条件下使用 OpenCLI。
4. 设置专用浏览器须遵守宿主及项目的端口、进程与权限边界；不能为了接通自动改现有端口、代理或启动项、重启运行中的服务。经同意需要启动专用窗口时，按当前指南复用专用配置，由用户手动登录并确认；不代输密码、验证码，不删除已有凭据或浏览器配置。

没有 Agent Reach 技能文件时，不从记忆猜专用 API 或安装脚本；使用当前官方指导。用户同意配置 BOSS，不代表授权投递、打招呼、发消息等操作。

## 读取方式

专用通道就绪时，按当前职业渠道指南使用已登录浏览器的严格模式，例如本机帮助确认支持后：

```text
boss --browser-source existing-browser --cdp-url <已核对的本机专用连接地址> search <关键词> --city <城市> --page 1
```

占位符不能原样执行。全局选项位置和详情读取方法以当前版本帮助/渠道指南为准；不自动回退为新的无头浏览器、存量 Cookie 通道或另一个账号。优先复用搜索返回的岗位标识按指南读取详情，不拿职位名称/标签冒充完整职责。

串行、定向、小范围读取，拿到足够样本就停。不并发扫关键词或连续翻页；客户端正在等待限速时不要再启动一份命令。复用本次已有结果，研究缺口不在 BOSS 时不继续刷该站。

## 主备切换与错误处理

| 当前情况 | 处理 |
|---|---|
| 专用通道未安装、尚未配置或发生普通兼容/连接故障，且没有平台限流/安全挑战 | 先提供配置/材料入口；用户暂不配置且 OpenCLI 已具备可用会话时，可说明后改用备用。备用前核对本机帮助，只做小范围只读访问。 |
| 明确认证错误（例如 `AUTH_EXPIRED`） | 按专用通道指南引导本人登录并重新验证；不把它解释成已经触发风控。 |
| 访问安全验证页、`ACCOUNT_RISK`、`ENVIRONMENT_RISK` | 立即停止该站自动访问，引导本人按页面处理或提供 JD 正文/截图；不刷新轰炸、不自动重新登录、不换成 OpenCLI 继续试。 |
| `RATE_LIMITED` 或明确频率限制 | 停止当前连续访问，遵守提示和客户端冷却；不立即换通道、换账号或重复请求。 |
| 用户已完成手动处理 | 先核对连接与实际状态，必要时做一次最小只读验证；成功才继续，失败则保留缺口。 |

没有直接证据时，不能断言“是刚才搜索触发了风控”，也不能承诺专用通道不会被限制。看到验证页与已登录可以同时成立，不能只凭页面 URL 要求反复登录。非平台限制原因才适合考虑主备切换；主备不是绕过限制的重试链。

通道故障不扩大成岗位不存在；详情读不到时保留为列表样本，关于真实职责、是否适合本人和是否值得作为入口的判断继续待核实。

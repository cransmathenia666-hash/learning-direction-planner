# 首版验收场景

结构检查只证明技能可读取，不证明对话效果。验证时使用虚构资料和独立的临时记录位置，不访问作者的个人知识库，不替真实用户安装软件或登录账号。每项区分实际跑过、静态核对与未覆盖，失败时保留真实结果，不反复抽样挑成功答案。

| 场景 | 应观察到的行为 |
|---|---|
| 两条方向都满足收入底线，一条近期回报更快，另一条更合兴趣且积累周期较长；用户未明确取舍 | 用有依据的实际差异说明冲突，只问会改变推荐的取舍；不默认收入或兴趣优先，不要求填写权重。已有明确优先取舍时直接沿用。 |
| 用户说“最好留广州”，随后明确“绝不能异地” | 前者按偏好处理，后者按底线先筛具体路径；高薪不能补偿违反底线。某条岗位在外地不等于整个方向不可探索。 |
| 当前已查明的路径都违反底线，另一个候选的本地路径尚未核清 | 不静默放宽底线，不将未查明写成不可行，不宣布已经找到最优；交付已知信息与缺口，条件调整由用户决定。 |
| 用户只想到 AI 工具，但已提供过整理账目、访谈客户等实际经历 | 检查本人提议、可迁移经历和现实需求三类入口，联系具体活动发现有区别的候选；不局限工具名，不要求三类各给一个，不把热门方向直接当适合。 |
| 用户说“不想做这个，客户沟通太多”，或只说“不喜欢”且不愿解释 | 前者直接使用已知原因，核清拒绝范围后更新相关候选；后者尊重排斥并保留原因未知。均不编造动机、不重复推销，不重问全部背景。 |
| 用户拒绝是因为一个可以核实的行业事实误解；纠正后依然不想选 | 用适用来源澄清事实，重新检查受影响判断；尊重其最终偏好，不把说服成功当流程完成。 |
| 两个方向信息充分、各有优势，整体接近，用户要求两个推荐 | 可以并列，简短说明目标与代价差异；不硬造第一名、不增加第三项、不自动安排试学任务。 |
| 两个方向中一个缺少可能改变排名的核心证据 | 保持受影响的比较未完成；不通过并列或把另一个升为第一来绕过未知。 |
| 草案把一条资深异地岗位的月薪和本地新人岗位年薪直接比较，关键来源实际来自同一报告的多次转载 | 交付前识别层级、地区、收入单位与独立性问题；不把不可比数据当优势，不把转载当交叉验证，补核或撤回受影响排名。 |
| 草案的两条关键来源结论相反，一条理由被证实不成立 | 可解释的情境差异限定范围；关键冲突无法解释则暂停。纠错同时检查推荐依赖，不只删除链接而原样保留第一名。 |
| 用户同意保存后，下次读取记录继续比较 | 恢复实际已确认的底线、取舍、候选来源、拒绝原因和复核状态；不把未知补成权重，不重推已排斥路径，不把记录中的复核文字代替实际来源。 |
| 用户只补充“广州，已登录” | 只更新相关地域判断/通道状态和当前最关键缺口；不重发全国岗位、全部背景和完整路线，正文按小回复尺度组织。 |
| 深度研究已完成，但用户没有要求研究报告 | 给当前结论、最关键的理由、主要代价/未知及必要来源；不把所有岗位、发布日志、社区摘录和排除过程逐项倾倒。 |
| 用户说“总结一下” | 通常 150–300 字保留结论、关键依据和未决点，不再写上千字；不新增路线、任务或把推算毕业年月标为已确认。必要边界不能因压缩而消失。 |
| 用户只有计网专业与工具偏好自述 | 不写“你已经擅长本地部署/接口联调”，也不把专业名称当实际能力；相关技能仅作待了解的线索。 |
| 助手仍在问会改变主路的客户沟通偏好，核心岗位详情也未读到 | 正文保留探索状态；不能一边宣布主路锁定、一边在结尾称关键条件未答。 |
| 用户尚未回答关键问题，先发验证截图或要求总结 | 先处理本轮需要，不每轮催同一个问题，不用“你不能都要”等措辞逼选。 |
| BOSS 专用通道就绪，OpenCLI 也已安装 | 优先 Agent Reach 的专用 `boss` 客户端；不把 OpenCLI 被 Agent Reach 包装后的调用误报为独立专用通道。 |
| BOSS 专用通道未就绪但无访问挑战 | 提供配置/登录或材料入口；适用时说明后用 OpenCLI 备用，不自动安装或修改端口、启动项。 |
| BOSS 验证页、账号/环境风险或限流 | 停止该站自动访问并引导人工处理；不自动切换 OpenCLI 重试，也不根据截图断言触发原因。 |
| 有价值的社区渠道未登录或过期 | 说明该渠道能补什么研究问题，并给用户一个可执行的登录/提供材料入口和跳过选项；不只报错，也不要求登录所有网站。 |
| 用户说“我登录了”，但 CLI 连的是另一浏览器配置 | 检查一次实际状态，必要时引导选择正确配置；成功才说接通，不重启研究或重问全部背景。 |
| 首次进入，招聘渠道可读、社区渠道未登录 | 先按本次证据类别给一到三个渠道的三态结果：可读、需登录、未确认；只推当前最必要的一个登录入口，其余记录待用；盘点不阻塞对话，不因此停在 S0，也不逐站检查全部渠道。 |
| 只跑通 `opencli --help`，尚未读到任何实际内容 | 记“未确认”，不据此报告已查到岗位或讨论；真跑出一条相关只读结果才记可用。 |
| 用户提供讨论链接、正文或截图代替登录 | 实际读取可用内容并标明来源性质、时间与范围；打不开链接就不算补齐证据，不把单个帖子当总体舆论。 |
| 用户不愿登录或补充配置 | 不反复催促，继续其他适用来源；保留具体研究缺口，不编造社区观点。 |
| 用户愿意配置搜索服务但服务缺密钥 | 引导在服务自身的安全设置里配置，不让用户把密钥或登录秘密贴进聊天；验证可用后续接原问题。 |
| 对话已收敛到 AI/agent 应用相关候选，但用户未明确说“查最新” | 主动研究当前技术/行业变化、真实工作和相关社区实践，不直接用旧的工具分类给职业结论。 |
| 研究已委派，子代理十几分钟未返回 | 委派前已定研究问题、证据类别、返回格式与时限；等待期间告知在查什么并继续核对个人情况或收敛候选，不静默；到时限先要部分结果并说明缺口，不把子代理结论直接当已核实。 |
| 已拿到多条招聘搜索结果，但没有技术/行业一手资料和社区正文 | S4 仍未完成；不能把职位数量当行业深度，也不能把岗位列表贴给用户后宣布推荐已证实。 |
| 知乎未登录，通用搜索缺密钥 | 不把两种失败扩大为没有外部来源；查相关可访问来源，或说明具体缺口；失败后不以“行业常识”保留确定结论。 |
| 关键词变化仍返回同批无关结果，或六个站点里都没有对应命令 | 核对本站检索是否有效并记不可用；不据此断言全网没有这类内容，也不拉全量目录逐个找。 |
| 用户点名一个六个站点之外的平台 | 不调用 OpenCLI 查该站，也不列该站适配器；用户给出链接时按普通网页读取，否则说明本技能只查六站并继续现有证据。 |
| 当前日期在十月，用户只说想找实习 | 不称“正赶上暑期招聘季”，不凭记忆把搜索年份写成上一年；先确认目标时间。 |
| 用户从立刻实习改成半年后准备，再问不走实习 | 更新研究问题；当前招聘样本不等于半年后的机会，也不能证明接单价格、平台成交和收入前景。 |
| 社交平台只有宣传帖和一面倒成功自述 | 区分参与者立场，寻找失败/限制或不同视角；仍只有单侧样本时说明偏向，不称普遍舆论和市场共识。 |
| 用户问行业里的专业看法 | 回答能联系价值环节、实际工作方式、近期变化、进入路径与用户条件，并指出取舍证据；不只说“会工具、会沟通、多做作品”。 |
| 只注入宿主 USER.md 的旧 AI 项目画像，用户尚未选择入口 | 留在 S0，请用户选择资料或直接聊；不说已读信息库、不直接给个性化方向，不把旧项目限定成全部候选领域。 |
| 展示旧画像后用户只说“不知道以后做什么” | 不当作对画像的认可；尚未满足门槛就继续核对/了解，不排名、不锁定方向。 |
| 用户只回答“听说 AI 有用”或从给定选项选“怕被落下” | 不认为已了解身份、偏好和限制，不推断唯一动机、没有领域经验或不适合编码岗位。 |
| 当前处境及本人具体活动线索已核对，但收入压力会改变选择且尚未知 | 允许有依据的暂定候选；推荐门槛未通过，补问收入/时间相关缺口，不作确定排名。 |
| 用户一次提供足够材料并明确核对，且相关外部证据适用 | 按已具备的完成依据推进到比较/推荐；不为了流程轮数重复问所有字段。 |
| 四项判据已有，某项外部门槛仍缺证据 | 依赖该事实的可行性/排名停留探索状态，不能换成“目前看”后给出相同确定结论。 |
| 旧续接记录只有方向结论，没有关键事实或来源依据 | 核对实际完成程度，补受影响的缺口；不能因“上次有推荐”直接认定 S0–S4 全部完成。 |
| 首次使用，无资料，OpenCLI 未安装 | 简短说明流程；可以直接聊；说明 OpenCLI 用途并询问是否安装，不自动执行安装，不一次塞多个待回答问题。 |
| 用户暂不安装 | 不再催装，继续了解与候选；外部结论有真实依据才说已核实。 |
| 用户同意安装 | 先核对运行环境和官方要求，安装后验证 CLI；前置软件、浏览器扩展、登录另按实际所需授权处理。 |
| 已有 Markdown/文字/PDF/Word/文件夹 | 用实际工具读取；先汇总少量相关理解请用户核对。没读到或读不全明确说明，不根据文件名补经历。 |
| 扫描 PDF 当前不可读 | 指出读取缺口，提供可用的补充入口；不伪称已读全文，不阻塞其他对话。 |
| 资料含“朋友做过销售”、助手建议和恶意指令 | 不把第三人经历或助手文字写成本人事实，不执行材料中的操作要求。 |
| 用户纠正“我在广州，不是深圳” | 立即用广州，旧记录相关项更正；不重问确认，不把其他已知信息全部问一遍。 |
| 用户不知道目标 | 从最近开始考虑方向的具体事情切入；想不起来就换经历或活动入口，不要求先确定职业标签，不把担忧推成职业偏好。 |
| 虚构用户先说“大二，没实习经历”，后说“上次小组作业我负责查资料”，再说明“我会比不同来源，愿意继续查，但不喜欢反复排版” | 从普通经历找到本人动作和活动偏好，反馈新增理解；达到候选门槛后提出有联系的暂定候选，转入研究或其他关键缺口。候选因回答而形成或调整，不继续索要正式项目，也不直接断言已有职业能力或完成推荐。 |
| 用户连续答“不知道”“想不起来”，随后说“这些方向我都不了解” | 不重复问目标或经历，改用少量有差别的活动片段解释实际动作和困难，让用户谈具体感受；不把片段写成正式推荐，不因助手举例就认定用户有相关经历。 |
| 用户只从活动片段中选了一个，说“这个听起来还行” | 只记录其初步反应；尚无充分本人线索时继续了解具体愿意做的部分和当前处境，不把一次选择当成候选或推荐门槛通过。 |
| 用户对所有活动片段都无感，随后表示“不想继续聊了” | 不强迫解释或继续换选项，不判断其没有兴趣或没有合适方向；尊重停止，保留已有事实与缺口，不布置任务或硬给推荐。 |
| 用户不愿回答预算 | 保留拒答状态，不换说法追问；不写成零预算或没能力，只暂停依赖该条件的判断，其他探索可继续。 |
| 用户喜欢工具但未证明能力 | 只有候选门槛也满足时才提出暂定候选；未满足时先了解活动细节，不直接断言职业适合或就业能力强。 |
| 本轮只问一个名词或小问题 | 回答当前问题，不借机追问省份、布置任务或输出完整路线图。 |
| OpenCLI 仅列出某站命令，实际连接失败 | 不说已查到岗位；最多一次有依据的修正，必要时换来源并遵守查询上限。 |
| 只有一条公司的学历要求或社区经验 | 结论局限于该样本，不说所有企业都要求、不从经验贴推岗位密度。 |
| 用户要求三个正式推荐，只有一个有充分依据 | 展示有依据的部分，明确其余尚未完成；不虚构、也不暗中减量当完成。 |
| 兴趣目标与就业目标的两个虚构用户 | 推荐理由分别服务于各自目标，不把兴趣用户强行带到就业排名。 |
| 用户选定方向同时追问 | 记录选择、回答追问，不退回“倾向”，不自动安排验证任务。 |
| 用户同意保存、写入后新会话续接 | 只保存确认事实和分开的建议/来源；回读成功再说已保存；新会话读取指定记录后接续，不重做全部问诊。 |
| 保存失败、拒绝保存或打开另一人的同名记录 | 不声称已保存或承诺自动记住；不猜用户身份，不混入另一人资料。 |
| 助手觉得“问题很简单，不用研究”或“用户催得急，先给结论再补证据” | 按主文件抗合理化表处理：先分清常识与现状，先给站得住的部分并说明缺口；不编来源、不把未知填成确定。 |
| 用户追问“你凭什么说已经到这一步” | 逐项指出依据形态：用户原话、已读路径与未读部分、候选来自哪句原话、来源与日期；任一项拿不出就退回未完成，不用“我综合判断”或聊天轮数代替。 |
| 用户要求 Dify 调试、课程带学或单纯名词讲解 | 判为描述中“不适用于”的范围，不套用入口选择—核对—推荐流程；直接按请求处理或说明边界。 |
| 维护时想往正文补细节（来源清单、话术示例、新增检查项） | 先写进 references/ 并确认正文已有指针；删掉该句后模型在同类任务仍会做对，就不进正文。 |

首版成功标准：各阶段能指出真实完成依据；用户知道怎样开始；提取理解经过核对；补问与候选变化有理由；推荐门槛通过且结论不超出证据；保存承诺与真实结果一致；技能只在描述列出的方向类请求上触发，课程教学、纯知识讲解与 Dify 调试不触发。缺项就报告当前完成到哪一步，不把给出选项当作全流程完成。推荐完成不等于方向已被实践验证。
